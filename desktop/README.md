# PUBG Marker Overlay — технический пробник Windows

Это первый этап проекта. Пока показывается прозрачный тестовый крест, а не метки карт. Проверяются видимость поверх игры, клавиши, пропуск мыши и фокус. Полная калибровка/метки/линейка начинаются только после успешной проверки этого этапа в PUBG «без рамки».

Подготовленный ZIP находится в рабочей среде: work/release/pubg-marker-overlay-probe-0.1.0-windows-x64.zip. Архив распаковывается целиком; запуск exe не требует Node.js или инструментов разработки. Реальный запуск в Windows/PUBG пока не проверен.

## Собрать и запустить на Windows x64

Нужны Node >=22.13.0, Python 3 и Visual Studio 2022 Build Tools с «Desktop development with C++». В PowerShell, находясь в папке desktop:

```powershell
npm ci
npm run native:build
npm test
npm run dev
```

Выберите две разные F-клавиши: дополнительное переключение слоя и управление. Нажмите «Начать проверку», затем вернитесь в PUBG. M показывает/скрывает крест, сохраняя обычный ввод игры; управление переключает просмотр/панель. В просмотре клики и колесо проходят вниз. Esc в панели скрывает слой. Крестик полностью завершает приложение. M работает и вне PUBG: состояние игровой карты не определяется. В interact фокус у приложения, поэтому M не обязан закрыть игровую карту — используйте дополнительную клавишу и повторно синхронизируйте состояния вручную.

Пробник не читает память/файлы/трафик игры, не делает скриншоты и не отправляет искусственный ввод. Raw Input регистрируется на окне самого приложения. Ввод не записывается. Просмотр не активирует окно. Во время выбора клавиш в нашем окне действия приостановлены. Временный интерфейс пробника ограничивает назначения F1–F24; произвольные комбинации будут реализованы на этапе полноценных настроек.

## Проверить обычное нижнее окно

```powershell
npm run test:windows
```

Откроются окно запуска и отдельное нижнее окно с полем текста. Начните проверку и вернитесь к нижнему окну. Нажимайте M, удерживайте M, нажимайте Ctrl/Shift+M: нижнее окно получает обычный ввод, слой меняется один раз на нажатие обычного M. Проверьте клики, колесо, переход interact/view, Alt+Tab и выход. Это ручная проверка; её команда не выдаёт автоматический PASS. Успех второго окна не заменяет PUBG.

## Портативная сборка

```powershell
npm run package
npm run verify:package
```

Forge создаёт ZIP в out/make/zip/win32/x64; внутри полная папка с exe и необходимыми файлами. Проверка проверяет распакованную сборку в out, присутствие настоящих PE-файлов exe/.node и локального UI. Это не проверка античита или поведения в игре. Запуск собранной версии не требует Node, Python или C++ Build Tools и не обращается в сеть. Portable-data создаётся рядом с exe; распакуйте в доступную для записи папку.

Workflow зарегистрирован в main, но GitHub отклоняет запуск: Actions отключён для владельца. Предварительный релиз собран локально через Zig; сайт не изменён.

## Проверки в Linux

```sh
npm ci --ignore-scripts
npm test
npm run build
npx playwright install chromium
npm run test:ui
```

Linux проверяет JS-логику, UI и локальную сборку renderer. Windows .node, прозрачность/пропуск событий ОС и PUBG здесь не проверяются. npm run native:build в Linux намеренно завершается с сообщением об отсутствующей Windows; stub вместо Windows-модуля не создаётся.

Результаты реального испытания заполняются в docs/audits/windows-overlay-validation.md репозитория. Не считать этап 1 завершённым, пока в протоколе нет фактических данных Windows/PUBG.

## Кросс-сборка пробника в Linux

Использованы Zig 0.14.1 и официальные заголовки Node 22.13.0. Из корня репозитория выполните `node desktop/tools/build-cross.cjs /путь/к/zig /путь/к/include/node`, затем в desktop — `npm run build` и `ELECTRON_GET_USE_PROXY=true npx electron-forge make --platform=win32 --arch=x64`. Обычная команда `npm run package` предназначена для Windows. Перед публикацией кросс-сборки отдельно проверяются PE x64, регистрационные экспорты, системные зависимости и наличие всех используемых Node-API функций в упакованном Electron. Кросс-сборка не заменяет запуск на Windows.
