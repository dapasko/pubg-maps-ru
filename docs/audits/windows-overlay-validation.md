# Проверка Windows marker overlay — 2026-10-11

Статус: реализован первый технический пробник. Это не готовый оверлей меток. Этап 1 не завершён, пока нет реального испытания Windows/PUBG. Этапы 2–7 не выполнялись: план запрещает строить остальной интерфейс до проверки применимости.

## Проверено в Linux

- Исходный npm test: 31 тест, 0 ошибок.
- Desktop npm test: 23 теста, 0 ошибок (повтор M, модификаторы, приостановка, очистка Raw Input lifecycle через OS test double, режимы окна, пути portable, фильтры упаковки и отказ проверить отсутствующую Windows-сборку).
- Desktop npm run build: локальная Vite-сборка технического интерфейса.
- Desktop npm run test:ui: Playwright проверил настройки, одинаковые назначения клавиш, видимость панели и интерфейс нижнего окна. Stub IPC только в браузерном тесте; нет stub вместо native module в приложении.
- Нативная сборка в Linux намеренно отказалась: Windows x64 отсутствует. Её результат не считается PASS.
- Проверки в Linux не доказывают прозрачность/пропуск мыши на Windows или совместимость PUBG.

## Точный состав пробника

Electron main + локальный технический интерфейс, Node-API C++ Raw Input на собственном окне, три режима окна, M и две выбираемые F-клавиши, ручное окно проверки нижнего ввода, локальные пути данных, ZIP workflow. Меток, карт, калибровки и линейки в пробнике пока нет. В пробнике настройки клавиш не сохраняются между запусками; сохранение относится к задаче 3/4.

Нет чтения памяти/файлов/трафика PUBG, захвата изображения, поиска процесса игры или искусственного ввода. Работа с HWND для foreground относится к оконному менеджеру Windows, не к данным игры. Не ведётся журнал клавиатурного ввода.

Независимый обзор выявил три Important-проблемы: восстановление фокуса при внешнем blur, общие VK для левых/правых модификаторов и ненадёжность access(W_OK) при Windows ACL. Исправления подтверждены RED→GREEN тестами, 23/23 зелёными. Дополнительно при регистрации запрашиваются только текущие состояния назначенных клавиш и модификаторов средствами ОС; ввод не журналируется.

## Windows-сборка — 2026-10-11

Workflow зарегистрирован в main отдельным CI-коммитом 460171d. Запуск отклонён HTTP 422: Actions has been disabled for this user. Поэтому Windows x64 ZIP собран локально: Zig 0.14.1, официальные заголовки Node 22.13.0, Electron 44.7.0 Windows x64, Forge 8.0.1. Вариант кросс-сборки разрешает Node-API только в собственном исполняемом файле Electron; обычный MSVC/node-gyp путь сохранён.

Свежие проверки: 25/25 тестов, production renderer, браузерные UI-проверки, проверка упакованных ресурсов, целостность ZIP. PE-модуль x64 экспортирует napi_register_module_v1 и node_api_module_get_api_version_v1; все 21 используемая функция Node-API найдены в Electron. Импорты модуля — только USER32, KERNEL32 и системный Universal CRT, без node.exe и внешних библиотек компилятора. Независимый обзор исходников кросс-сборки не нашёл блокирующих дефектов.

Предварительный релиз: https://github.com/dapasko/pubg-maps-ru/releases/tag/overlay-probe-v0.1.0 . SHA256SUMS.txt содержит контрольную сумму ZIP. Эти проверки не подтверждают запуск в Windows или PUBG: все ручные строки ниже остаются NOT RUN.

## Решения исполнителя

- Изолированная рабочая ветка в существующей игнорируемой work/: текущий main не меняется; если нужен другой порядок, изменения можно перенести отдельным коммитом.
- node-gyp 12.2.0 вместо latest 13.1.0 сохраняет заявленную совместимость Node >=22.13.0; при необходимости потребуется обновить зависимость и пересобрать Windows модуль.
- Временный TypeScript интерфейс пробника вместо React продуктового UI: проверяется техническое основание без преждевременной разработки полной панели; интерфейс заменяется на этапе 4.
