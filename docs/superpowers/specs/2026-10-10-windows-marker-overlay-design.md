# Оверлей меток PUBG для Windows — проект решения

Статус: основа Electron выбрана пользователем; 2026-10-11 пользователь запросил реализацию. Подготовлен технический пробник задачи 1; полная реализация зависит от обязательной проверки Windows/PUBG. Документ фиксирует ответы в чате и предложенные инженерные решения; числовые пределы ниже — предлагаемые критерии, а не результаты испытаний.

## Назначение и согласованные требования

Портативное приложение показывает существующие метки сайта поверх встроенной карты PUBG на Windows 10/11 x64. Игра используется в режиме «без рамки». Один монитор, разрешение может меняться. Пользователь выбирает карту и профиль экрана вручную.

- Приложение не читает память, файлы, сетевой трафик игры, не определяет позицию игрока и не получает состояние игровой карты. Нет захвата экрана, распознавания изображения и отправки искусственных нажатий.
- В обычном использовании фон прозрачный: видны только метки. Локальная картинка разрешена исключительно для калибровки.
- Клавиша M переключает слой всегда, пока приложение запущено, включая другие программы. Дополнительные клавиши переключения слоя и режима управления настраиваются пользователем.
- Просмотр пропускает мышь в нижнее окно и не забирает фокус. В режиме управления появляются компактная панель, выбор карты/слоёв, масштаб, сброс, настройки и линейка.
- Колесо масштабирует слой вокруг центра откалиброванной области карты. Стрелки меняют смещение; перетаскивания слоя мышью нет. Значки сохраняют отдельный экранный размер.
- Сброс возвращает сохранённую калибровку. Временные масштаб и смещение не переписывают её автоматически.
- Все существующие категории шести карт доступны; видимость сохраняется для каждой карты. Новые данные pubg.gs не импортируются этим проектом.
- Значки выглядят как на сайте; размер и прозрачность настраиваются. По нажатию нет карточек, заметок и действий.
- Калибровка по двум опорным точкам, проверка третьей и ручная корректировка. Отдельная запись для каждой карты и профиля разрешения.
- Линейка между двумя точками работает и отображается только в режиме управления. Планировщика полёта нет.
- Полностью офлайн во время использования. Обновление — скачиванием новой версии вручную; нет автоматической проверки, телеметрии и загрузки сайта.
- ZIP, без установщика. Пользовательские настройки и профили лежат рядом с приложением. Крестик завершает всё приложение, без трея.

## Состав приложения

1. Electron main управляет двумя окнами: обычное окно настройки/запуска и прозрачное окно оверлея на весь монитор. Оверлей выше обычных окон Windows; применимость к PUBG проверяется отдельно. Закрытие любого основного окна через явный «Выйти» или крестик панели завершает приложение.
2. Renderer React/TypeScript загружает только упакованные локальные ресурсы. Отдельный компактный интерфейс; большая страница сайта не загружается целиком. Используются исходные SVG, данные и функции нормализации/подписей репозитория.
3. Небольшой C++ модуль Windows на Node-API регистрирует Raw Input на принадлежащем приложению HWND. Он получает события клавиатуры, а не данные PUBG. Не внедряет код в другие процессы. Нативная часть предварительно собрана для Windows x64 и входит в ZIP.
4. Чистые модули геометрии, состояния и настроек тестируются без Electron/Windows.

Планируемая структура: `desktop/` с собственным package.json, Vite-конфигурацией, Electron Forge и ZIP maker. Корневые сборка и публикация сайта остаются отдельными. Версии Electron, Forge, Vite и инструментов C++ фиксируются при первом техническом этапе вместе с lock-файлом после проверки совместимости. Node сборочной среды удовлетворяет существующему ограничению репозитория >=22.13.0.

Нативный модуль использует `RegisterRawInputDevices` с `RIDEV_INPUTSINK`, без `RIDEV_NOLEGACY`; Electron принимает WM_INPUT через своё окно. Источник пользовательских горячих клавиш один, чтобы одно событие не обрабатывалось дважды. Полученные клавиши не пишутся в журнал; приложение сравнивает только необходимые назначения и состояние модификаторов. Доступ к файловой системе разрешён только main, renderer получает узкий проверяемый IPC API, `nodeIntegration=false`, `contextIsolation=true`, `sandbox=true`. Запросы к внешним адресам и произвольные переходы запрещены.

## Управление и ограничения синхронизации

Состояния: `hidden`, `view`, `interact`; калибровка — отдельный режим инструмента внутри `interact`.

| Действие | Результат |
| --- | --- |
| Запуск | Окно настроек; оверлей скрыт. Пока нет валидного профиля, M не показывает некалиброванные метки, но обычное нажатие не блокируется |
| M или назначенная клавиша слоя | hidden → view; view/interact → hidden |
| Назначенная клавиша управления | view ↔ interact; из hidden не показывает слой |
| Возврат в view | Панель и измерение скрываются, мышь проходит в нижнее окно |
| Esc в interact | Скрывает слой; не отправляет Esc в игру программно |
| Потеря фокуса interact | Переход в view, прекращение повтора стрелок, скрытие линейки |
| Закрытие приложения | Удаление регистрации ввода, закрытие обоих окон и завершение процесса |

M обрабатывается один раз на физическое нажатие; удержание не вызывает многократного переключения. M с Ctrl/Alt/Shift/Win не считается отдельным M, если соответствующее сочетание не назначено. При записи комбинации и вводе текста в собственных настройках действия горячих клавиш приостановлены: ввод не должен случайно переключать слой. Дополнительные комбинации при первом запуске пользователь назначает явно; нельзя совпадать с M, Esc, стрелками и друг с другом. Проверяется конфликт внутри приложения; отсутствие конфликтов с любыми программами/назначениями игры не обещается.

В `view` нельзя использовать регистрацию M как захватывающей глобальной команды: PUBG должен получить обычный ввод. В `interact` фокус получает наше окно: M может скрыть слой, но игровая карта останется открыта. Закрытие игровой карты другим способом, чат PUBG, и изменения её масштаба тоже могут рассинхронизировать состояния. На странице первого запуска объясняются отдельное переключение слоя и возврат к исходной карте; не заявляется автоматическое определение открытия карты. Возврат фокуса проверяется через сохранённое перед взаимодействием HWND обычными средствами Windows; приложение не ищет процесс PUBG. Ограничения Windows на установку фокуса проверяются на целевой машине; не применяется синтетический ввод.

## Калибровка, масштаб и пиксели

Исходные координаты: `markerPoint([northing,easting],mapId)` из `lib/map-geometry.mjs`. Для нормализованной точки u=(x,y): экранная точка в DIP равна `origin + sideDip * u`. Единый масштаб обеих осей, без вращения и искажения квадратного растра.

Для двух пар точек вычислить положительный `sideDip = dot(screenDelta,mapDelta)/dot(mapDelta,mapDelta)` и origin по среднему двух смещений. Отказаться от сохранения при совпадающих/слишком близких опорах, неположительном масштабе, нечисловых координатах или несовместимом направлении. Разнос опор >=0.25 нормализованной ширины карты. Проверочная третья точка удалена >=0.10 от прямой двух опор. Её ошибка после преобразования <=2 физических пикселей; при большей ошибке предложить повторить точки/ручную подгонку, без заявления «идеально».

Картинку для настройки показывать и скрывать по шагам мастера. Перекрестием пользователь указывает положение ориентира, видимого на игровой карте; скриншот не снимается. В конце калибровки перепроверить 5 ориентиров по центру и краям. Перед сохранением изображение выключается, точки сравниваются с игрой непосредственно. Пересохранять только явной командой «Сохранить калибровку».

Профиль экрана: id, имя, ширина/высота монитора в физических пикселях, scaleFactor Windows, пользовательская подпись разрешения игры. Отдельные состояния на карту: калибровка, слои; размер значков и прозрачность сохраняются в профиле. DIP и физические пиксели различать явно. Изменение размеров монитора/DPI скрывает слой и предлагает подходящий профиль; внутренний render scale PUBG не определяется. Неизменившиеся реальные границы игровой карты не требуют новой калибровки только из-за другого внутреннего разрешения рендеринга.

Предлагаемые значения: значки 22 DIP, диапазон 12–40 DIP; непрозрачность 1.0, диапазон 0.2–1.0; масштаб 1.0–8.0, колесо меняет в 1.1 раза за стандартный шаг. Стрелки 1 DIP, Shift+стрелка 10 DIP. Масштабирование держит центр области карты неподвижным и сохраняет ручное смещение. Слой обрезается фиксированной областью игровой карты, определённой калибровкой; метки не выходят на окружающие панели PUBG. Значки за рамкой не рендерятся.

Для каждого SVG фиксировать реальный якорь: у пинов — кончик, у симметричных пиктограмм — центр, без добавления внутреннего поля SVG к координате. Ошибка отрисовки якоря <=1 DIP; отдельно от неё измеряется ошибка калибровки. Данные с неизвестным режимом/версией остаются такими; оверлей не делает все точки подтверждёнными.

## Линейка и хранение

Клики по прозрачному полотну в interact задают A и B; третий клик начинает новое измерение. Значки сами не принимают клики. Координаты экранных точек переводятся обратно текущим преобразованием. Метры вычисляются из подтверждённых `provenance.raster.boundsCm` в data/maps.json: для нынешних шести карт ширина 8160 м, а не nominal sizeKm=8. Отсутствующие границы — ошибка данных, линейка отключена с понятным сообщением. Измерение — расстояние по прямой, не длина дороги или время движения.

На выходе из interact измерение очищается и не сохраняется. Измерение/калибровка отключают стрелочное перемещение и колесо на время выбора пары точек; для изменения преобразования сначала закончить/отменить выбор. Смена карты, профиля, сброс и новая калибровка очищают точки.

`settings.json` рядом с exe, `schemaVersion=1`, атомарная запись через временный файл и переименование, резервная предыдущая версия `settings.backup.json`. Нельзя молча сбрасывать повреждённый/неподдерживаемый файл: показать причину, сохранить исходник, дать создать новый профиль. Папка без записи — сообщение при проверке сохранения, без ложного успеха и без переноса настроек в AppData. Chromium userData/cache и журналы собственного приложения тоже направить в локальную подпапку portable-data; проверить фактические побочные записи Electron на чистой Windows.

## Дизайн и проверка

Панель в interact компактная, контрастная, с непрозрачной поверхностью: CSS backdrop-filter не способен гарантированно размывать игру под отдельным окном. На частые переключения горячими клавишами нет анимации. В view нет подсказок, панелей, линейки и изображения. Непрозрачность меток не снижает контраст панели.

Технический этап должен доказать на Windows без админ-прав: прозрачность без чёрного фона, видимость поверх PUBG «без рамки», сохранение обычного M в игре, пропуск мыши/колеса в view, переключение управления и завершение всего процесса. Проверить DPI 100/125/150%, разрешения 1920×1080 и 2560×1440, если доступны. Linux-браузерные тесты не заменяют эту проверку.

После калибровки независимые ориентиры <=2 физических px при исходном масштабе; преобразование туда/обратно численно устойчиво до 8x. Все категории и значки сохраняют координаты при изменении размера. Для скрытого слоя нет постоянного цикла перерисовки; для неподвижного view не требуется 60fps loop. Измерить CPU/RAM, p95 реакции на клавишу (цель <=100 мс) и влияние на frame time PUBG на машине пользователя; обещаний нулевого влияния нет.

Проверить ZIP офлайн под обычным пользователем, путь с кириллицей/пробелами, повреждённые настройки, перенос папки, обновление поверх прежней версии без перезаписи settings и полное завершение. Совместимость с античитом не следует из этих тестов; допустимость распространения и отсутствие подтверждения разрешения указывать отдельно в release checklist, без автоматического обхода ограничений.
