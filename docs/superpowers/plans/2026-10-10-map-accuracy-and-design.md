# Точность карт и дизайн в духе Apple — план улучшений

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Выполнять последовательно; не менять координаты без независимого эталона.

**Goal:** Совместить достоверное расположение объектов на всех шести картах с выразительным, удобным интерфейсом в светлой и тёмной темах.

**Architecture:** Изображение, геометрия и метки каждой карты получают общий паспорт источника и версии. Один преобразователь координат обслуживает метки, сетку и измерение. Интерфейс разделяется по назначению: выбор карты, слои, планировщик, карточка объекта; оформление использует общие токены двух тем.

**Tech Stack:** React 19, TypeScript, vinext/Vite, CSS, Node test runner. Браузерные проверки — Playwright; существующие расчёты остаются в чистых модулях `lib/`.

**Spec:** Запрос пользователя от 2026-10-10: исследовать смещение всех типов меток, сверить шесть карт с pubg.gs и составить полный план визуальных улучшений. Это предлагаемый план; большие новые функции не реализованы.

## Global Constraints

- Сохранить Эрангель, Мирамар, Викенди, Тэго, Дестон и Рондо.
- Сохранить светлую, тёмную и системную темы; выбор сохраняется локально.
- Не применять общий ручной сдвиг ко всем картам.
- Не выдавать точку возможного спавна за гарантированное появление объекта.
- Для координат использовать реальные границы растра, а не округлённое название «8 км».
- Поддерживать клавиатуру, сенсорные экраны, safe area, reduced motion/transparency и повышенный контраст.
- Не заменять изображения/метки до проверки соответствия их версий и прав на повторное использование источника.
- Публикация через существующую ветку main и статические файлы GitHub Pages; успешный push не равен подтверждённой публикации.

## Подтверждённые результаты аудита

- `data/markers.json`: источник pubg.plus, объявленная дата обновления 2026-09-11; 6 550 точек, все имеют конечные координаты внутри исходных границ.
- `tools/update-maps-from-pubg-gs.mjs` обновляет только erangel, miramar, rondo из cdn.wardo.gs; паспорт связи изображения и меток отсутствует.
- Для erangel в `lib/map-geometry.mjs` сохранена сентябрьская калибровка: -0.288 по обеим нормализуемым осям; по текущему номинальному масштабу это -9 м по каждой оси. Её валидность после замены изображения не установлена.
- Тест «масштаб меток» проверяет арифметику x * zoom / zoom, а не браузер и не положение игровых объектов.
- Обнаружена ошибка пропорций: карта в браузере имела 756.47×788.47 при окне 1024×1000 и 358×366.59 при 390×844. Исправлена через aspect-ratio:1. Это отдельный дефект отображения, а не доказанная причина несовпадения координат и объектов.
- Таблицы pubg.gs доступны через веб-инструмент, но прямой доступ к клиентским данным/тайлам из среды блокируется прокси HTTP 403 даже после разрешения пользователя. Полная поточечная сверка пока заблокирована.

## Review Focus

- Узкое высокое окно и открытая панель: карта остаётся квадратной и помещается в доступное пространство.
- Смена карты при активных измерении/полёте: старые координаты не переносятся на другую карту.
- Разные версии игровых данных и режимы: импорт не объединяет неподходящие точки.
- Плотные и совпадающие метки: выбор объекта остаётся доступным и однозначным.
- Заблокированные localStorage, недоступные тайлы и большие подписи: приложение сохраняет доступные действия и объясняет состояние.

## Этап 1 — точность данных, P0

**Files:** `lib/map-geometry.mjs`, `data/maps.json`, `data/markers.json`, `tools/update-maps-from-pubg-gs.mjs`; создать `data/map-reference-points.json`, `tools/audit-marker-alignment.mjs`, `tests/marker-alignment.test.mjs`.

**Interfaces:** `markerPoint([northing,easting], mapId) -> {x,y}` остаётся публичным интерфейсом. Паспорт карты хранит mapId, source URL, raster bounds, coordinate units, raster version, marker version, время проверки.

- [ ] Получить фактические клиентские данные и преобразование координат pubg.gs для всех шести карт после разрешения доменов в политике среды.
- [ ] Сопоставить одинаковые категории и режимы; отдельно отмечать отсутствующие в источнике категории, а не заменять их координаты догадкой.
- [ ] Зафиксировать минимум 12 независимо проверенных точек на карту: центр и четыре стороны; включить тайные комнаты, башни и транспорт. Не извлекать ожидаемые координаты из проверяемой функции.
- [ ] Записать для каждой точки исходную координату, эталонную позицию на растре, тип объекта, источник и версию.
- [ ] Создать падающий тест совпадения с эталонами; отдельно проверять максимальную и медианную ошибку каждой карты. Предлагаемый предел точности эталона — 2 пикселя на растре 8192×8192; согласовать при фактической точности источника.
- [ ] Проверить порядок осей, знак Y, начало координат, границы и размеры изображения. Разделить постоянный сдвиг, ошибку масштаба и отдельные устаревшие объекты.
- [ ] Исправить установленное преобразование или обновить конкретные координаты; прежнюю калибровку Эрангеля убрать только при доказанном соответствии новому растру.
- [ ] Сформировать отчёт добавленных/удалённых/перемещённых точек по каждой категории, проверить его до замены данных.
- [ ] Прогнать `npm test`, `npm run build`, исходный линтер и браузерный контроль на 100%, 200%, 400%, 800%, 1200%.

**Приёмка:** каждый объект из эталонного набора совпадает с соответствующим растром; одна и та же точка не дрейфует при масштабе и смене тайлов; датировка источников видна в паспорте.
